# ADR-093：全局搜索的 LLM 综合摘要与可点击引用

- **编号**：ADR-093
- **状态**：草案（待评审）
- **日期**：2026-10-14
- **决策者**：ACowork 架构组
- **关联**：ADR-009（Gateway / Runtime 工作区边界）、ADR-064/070（Gateway 零业务）、ADR-081（六源全局搜索）、ADR-082（记忆与对话存储）

## 摘要

全局搜索的价值不止是六个 tab 的结果列表，用户还需要一个跨来源、能快速回答“搜到了什么”的摘要，并能从摘要引用直接打开相关命中。当前 Desktop 主要只请求活动 tab，结果返回后也没有跨来源摘要。

本 ADR 决定：Desktop 在查询变化时并行请求六个适用搜索来源，各来源列表仍独立展示、沿用现有排序；来源结果逐个到达即可更新列表和进度。Desktop 将有界的命中摘要提交给当前 agent 的 Runtime，由 Runtime 使用已有 Provider 生成跨来源摘要。摘要用受限的结果 ID 标记引用；Desktop 只将通过本次结果集校验的 ID 渲染成可点击控件，并映射到现有类型化打开/定位动作。摘要生成失败不影响搜索列表；检索或 LLM 慢响应不能阻塞 UI。

## 1. 背景与问题

ADR-081 建立六个来源：文件、文档、项目、对话、记忆、Git。现有 [GlobalSearchDialog.tsx](../../../apps/acowork-desktop/src/components/search/GlobalSearchDialog.tsx) 大多在活动 tab 才发起搜索，因而没有一次查询覆盖全部来源的结果集。Runtime 的 [global_search.rs](../../../core/acowork-runtime/src/http/global_search.rs) 聚合记忆、对话、文件和 Git，但文档与项目由独立进程提供；各来源现有分数也不具备横向可比性。

现有结果行已经有按类型打开或定位的动作：文件打开到命中行、文档打开文档、项目/任务打开对应项、对话定位消息、记忆加载节点；Git 目前打开全局 Git log 视图。不能要求模型生成可执行 URL，也不能把模型输出当作 UI 标记语言。

## 2. 决策

### D1 — 六源并行检索，摘要是额外视图而非第七种排序

查询文本变化后，Desktop 并行请求当前 agent/workspace 下适用的文件、文档、项目、对话、记忆、Git 搜索。没有 agent、workspace 或索引能力的来源按既有语义跳过并说明原因。每个 tab 的结果列表独立更新，继续使用该来源的既有排序和交互；**不进行跨 tab 排序，也不改写各来源排序**。

适用范围遵循现有身份和数据归属：文档/项目仍使用其既有 Gateway 反代 API；文件/Git/对话/记忆仍使用所属 Runtime API。Gateway 只增加必要的透明反代，不做聚合、摘要或排序业务。

### D2 — 摘要由 Runtime 调用现有 LLM Provider

所有来源请求完成，或达到本 ADR 的检索截止时间后，Desktop 把查询和已返回的有限候选项提交给所选 agent 的 Runtime 摘要端点。候选项只含本次请求的 ID、scope、标题和截断 snippet；不上传完整文件、文档或会话，也不将 locator/payload 交给模型。Runtime 复用现有 Provider `chat()` 能力，不新引入模型 SDK 或 Gateway LLM 逻辑。

初始上限：每个来源最多取 20 条用于 UI；摘要最多消费每来源 5 条、每条 snippet 500 个 Unicode 字符，且总候选最多 30 条。超出部分仅保留在 tab 列表中，不送入摘要。模型输出上限 800 tokens。若输入裁剪仍超过 Provider 可接受上下文，摘要请求失败并按 D5 降级，不截断查询文本。

候选内容视为不可信数据：提示词明确要求忽略命中内容中的指令，只执行摘要与引用任务。模型不得改变搜索数据、调用工具或产生导航 URL。

### D3 — 摘要引用是受校验 ID，不是链接

Desktop 为每个摘要候选分配本次查询唯一 ID（如 `r1`），并保留 `ID → 原始类型化命中` 映射。Runtime 要求模型返回受限 JSON，摘要正文中的引用采用 `[[r1]]` 形式。UI 以普通文本解析正文，只把匹配本次提交候选集合的标记渲染为可访问的按钮/链接样式；未知、重复或格式错误的 ID 不可导航且不被当作 HTML 渲染。

点击有效引用时，Desktop 通过本地映射找到命中，并调用既有类型化动作，而非访问模型提供的 URL。文件/文档/项目/任务/对话/记忆直接使用当前已有目标动作。Git 使用现有 Git log 打开动作；若当前实现只能打开 log 而不能定位具体 commit，引用只切换到 Git tab 并聚焦该命中，不声称可打开尚不存在的 commit detail。

### D4 — 进度可见、结果逐步可用、交互不阻塞

搜索面板新增独立摘要区，不以摘要代替各 tab 列表。查询期间：

- 按来源显示“等待中 / 搜索中 / 已完成（数量）/ 无结果 / 跳过 / 失败 / 超时”；任一来源返回时立即更新该 tab，不等待其余来源。
- 汇总显示来源进度（例如“已完成 3/6 个来源”）；慢来源有截止状态，不无限等待。
- 搜索来源返回或截止后，摘要区显示不确定进度的“正在生成摘要”；摘要 LLM 调用期间列表仍可切换、滚动、打开结果。
- 新查询、关闭对话框或切换 agent/workspace 时取消旧请求并丢弃旧请求的迟到响应；不得用旧摘要覆盖新查询。
- 使用异步请求，不在渲染/事件线程执行检索、解析或 LLM 工作。

超时策略：六源收集自查询发出起最多等待 **8 秒**；到时以已经返回的结果启动摘要，并将未完成来源标记超时、取消其请求。LLM 摘要最多等待 **20 秒**。空结果不调用 LLM。期限可在实现后根据真实网络与模型耗时数据修订；前端进度提示不得伪装成精确百分比。

### D5 — 失败隔离与部分结果

单个来源失败/超时不阻止其他来源或摘要。摘要仅基于成功返回的候选，并在 UI 说明摘要所覆盖的来源/存在超时；没有候选时显示无命中状态。LLM 不可用、超时、输出不是合法格式、正文为空时展示简短可恢复提示，保留所有已返回列表，不以原始模型输出作为摘要。摘要按钮引用必须通过 D3 的白名单校验。

### D6 — 摘要生成是按查询触发的一次性请求

每次有效查询最多生成一份摘要；不在每个 tab 切换时重复调用。查询变化后取消前一代请求。MVP 不做 token 流式输出、搜索历史持久化、跨 agent 搜索或模型重排；LLM 阶段采用可见的不确定进度提示即可。

## 3. 明确不做

- 不跨 tab 合并或重排命中列表；不改动来源各自评分语义。
- 不让 LLM 生成或执行 URL、HTML、代码、工具调用或搜索条件。
- 不将完整私有文件、文档、对话内容发送给 Runtime；仅发送有界标题/snippet。
- 不让文档或项目数据所有者迁移到 Runtime；Gateway 仍只反代。
- 不因摘要失败隐藏或清空已检索结果。

## 4. 备选方案

| 方案 | 处理 | 原因 |
|---|---|---|
| 仅活动 tab 检索，再生成摘要 | 拒绝 | 无法满足摘要覆盖所有 tab 的要求 |
| 把六源检索/拼接放进 Gateway | 拒绝 | 违反 ADR-064/070 零业务边界；Gateway 不拥有 agent 私有数据 |
| 模型直接返回任意 URL 或 HTML 链接 | 拒绝 | 可伪造/错链，且把不可信模型输出提升为可执行 UI 内容 |
| 让 LLM 跨 tab 重排一个混合列表 | 拒绝 | 用户明确各来源列表独立查看；不同 scope 分数和语义客观不同 |
| 等所有来源和 LLM 全完成后再展示结果 | 拒绝 | 慢来源或模型会阻塞主要搜索交互，且无法提供渐进反馈 |

## 5. 影响与风险

- 查询时会同时触发更多来源请求；需沿用取消机制及每源/摘要输入上限，防止资源放大。检索由回车显式触发（见 [ADR-081 §4.5.1](ADR-081-global-search.md)），输入过程不发起请求——debounce 只降低频率、不降低量级：每敲一个字符仍会触发一轮六源并发加一次 LLM。
- 六个来源跨不同服务，超时后摘要是部分摘要而非完整性承诺；UI 必须展示覆盖/超时状态。
- LLM 可能给出不存在的引用 ID；前端白名单校验保证无效引用不会导航。
- Git 现有打开动作不一定能精确定位提交；MVP 按 D3 描述降级到 Git tab 命中聚焦。
- 摘要属于推理结果，不应作为搜索真相或持久化数据；原始搜索命中仍是定位依据。

## 6. 验收条件

1. 单次查询会并行启动所有适用来源；来源结果逐个到达后即可在对应 tab 浏览。
2. 摘要包含多个来源的结果时，正文引用可点击并打开/定位到映射命中；模型伪造 ID 不可点击。
3. 各 tab 顺序保持原有来源排序，tab 切换不额外触发摘要 LLM 调用。
4. 一个或多个来源失败时其他来源继续；达到 8 秒时可用已返回结果开始摘要。
5. LLM 最多等待 20 秒；期间 UI 可交互，失败后搜索列表仍可用且有明确提示。
6. 查询/agent/workspace 变化及关闭对话框后，旧响应不覆盖新状态。
7. LLM 请求只收到有界候选摘要，不含 locator/payload；仅 Gateway 做透明反代。

## 7. 回滚

可通过 Desktop 隐藏摘要区并恢复活动 tab 搜索触发行为回滚 UI，不影响各来源既有搜索 API。Runtime 摘要端点和 Gateway 反代可独立移除；不涉及数据迁移或持久化格式变更。
