聊天卡片视觉统一设计稿

设计目标：统一 chat session 与 execute session 的交互卡片，全项目 标题栏 + 内容区 结构。 交互形态只有两种：列表选择型（单选列表，用于 ask_question）和按钮操作型（即时动作按钮，用于 approval / pause / retry）。 每种卡片覆盖三个状态：待操作 / 已回答 / 已关闭。

布局策略（与 agent 气泡一致）：左侧缩进 ml-12 (48px = avatar 40 + gap 8)；宽度上限 max-w-[var(--content-max-width)]；实际宽度由内容自适应（shrink-to-fit），不撑满聊天框。

询问 (ask_question)
审批 (approval)
暂停确认 (pause)
失败重试 (retry)

一、ask_question — 列表选择型

适用场景：Agent 询问用户从若干选项中选择，附带"其他"自由文本。

▸ 待操作（Open）
💬 需要你的确认 4:32
您希望使用哪种数据库方案？
  • SQLite
    轻量内嵌，无需独立进程，适合单机部署
  • PostgreSQL
    生产级关系数据库，支持高并发
  • 其他
▸ 已回答（Answered）
💬 已回答
✓ 您选择了： SQLite — 轻量内嵌，无需独立进程
您希望使用哪种数据库方案？
▸ 已关闭（超时/取消）
💬 已关闭
— 问题超时关闭
您希望使用哪种数据库方案？

二、ask_question — 按钮快速选择型

适用场景：选项简短（≤4个），直接点击即提交，无需 Submit 步骤。

▸ 待操作（Open）
💬 Agent 询问 3:15
是否继续在当前分支上开发？
▸ 已回答
💬 已回答
✓ 您选择了： 是，继续当前分支
是否继续在当前分支上开发？
▸ 已关闭
💬 已关闭
— 会话已结束，问题自动关闭
是否继续在当前分支上开发？

三、审批卡片（approval）

适用场景：Agent 请求用户批准某个操作（命令执行、文件修改等）。

▸ 待审批（Open）
🔐 需要审批 5:00
Agent 请求运行以下命令
cargo build --release --all-targets
▸ 已批准
🔐 已批准
✓ 已批准执行
Agent 请求运行命令: cargo build --release --all-targets
▸ 已拒绝
🔐 已拒绝
✗ 已拒绝
Agent 请求运行命令: cargo build --release --all-targets

四、暂停确认卡片（pause）

适用场景：执行步骤需要用户确认后继续，或停止当前任务。

▸ 等待确认（Open）
⏸ 步骤确认 3:42
即将覆盖已有文件 src/main.rs
是否继续写入？
▸ 已继续
⏸ 已继续
▶ 用户选择继续
▸ 已停止
⏸ 已停止
■ 用户停止任务

五、失败重试卡片（retry）

适用场景：步骤失败后 Agent 询问用户是否重试。

▸ 等待选择（Open）
⟳ 步骤失败
命令执行失败（exit code 1）
error[E0308]: mismatched types — expected `String`, found `&str`
▸ 已重试
⟳ 已重试
⟳ 用户选择重试
▸ 已跳过 / 终止
⟳ 已跳过
→ 用户跳过此步骤
